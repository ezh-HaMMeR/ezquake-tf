# Перекраска серверных моделей TF2003

`progs/tfbody1.mdl` … `tfbody4.mdl` и `progs/tfheadless1.mdl` …
`tfheadless4.mdl` задают отображаемую команду суффиксом: синяя, красная,
жёлтая, зелёная. Встроенный скин 0–9 задаёт текстуру класса. Эти значения
используются и для живого шпиона, и для трупа, без чтения внешности владельца
из scoreboard. Смена класса, команды, цвета и отключение владельца поэтому
не изменяют внешность оставшегося трупа.

`TP_ApplyForcedColors` используется также обычными игроками. Индивидуальный
RGB-цвет команды имеет прежний приоритет над `teamcolor` / `enemycolor`.
Союзность сравнивается с командой текущего игрока/наблюдаемого игрока, а при
свободном наблюдении применяется команда `teamlock`. Для новых моделей
всегда используется команда из имени, включая маскировку шпиона.

## Восстановление областей перекраски

Генератор TF2003 удаляет все индексы 16–31 и 96–111 из запечённых текстур.
Сопоставление запечённых цветов с палитрой не позволяет однозначно отличить
одежду от остальных частей текстуры. Клиент содержит сжатые маски из исходных
текстур, которыми пользовался генератор: PCX классов для `tfbody`, встроенные
скины исходной `headless.mdl` для `tfheadless`. Маски содержат только позиции
и исходные градации двух диапазонов одежды.

При загрузке сохраняются все десять встроенных запечённых скинов каждой
модели. При рисовании изменяются только включённые диапазоны маски; остальные
пиксели берутся из серверного скина. Геометрия, UV, анимация и текстура класса
не заменяются. RGB-градации вычисляются так же, как для обычных игроков.
Сохраняются fullbright-пиксели для обоих рендереров.

Текстуры кэшируются по модели, встроенному скину, союзности и выбранным
цветам. Изменение настроек проверяется при рисовании, в том числе для трупов
без colormap. `teamcolor off` / `enemycolor off` отключают соответствующее
принудительное правило; индивидуальные цвета команд по-прежнему имеют свой
приоритет. `gl_nocolors 1` полностью возвращает исходную серверную текстуру.
Несовместимые размеры/число скинов оставляют исходный вид модели.

Маски встроены в EXE: дополнительные клиентские PCX/MDL не требуются.
Их воспроизводимая проверка против всех 80 запечённых скинов:

```powershell
py -3.13 tools/build_tf_model_masks.py --tf-root C:/PythonProjects/TF2003 --gamedir C:/Games/qwtf/fortress --check
```

## Проверка

`tf_model_skin_tests` проверяет восемь имён, все 20 масок классов, размеры,
палитровую инверсию, RGB-градации, раздельные диапазоны, сохранение остальных
пикселей/fullbrights, изменение цвета и отключение перекраски.

Для проверки реального рендеринга создаётся изолированное MVD с обычным
красным Soldier, синим Spy в красной маскировке Soldier, красными трупами
`tfbody2`/`tfheadless2` с colormap 0 и обычным синим Soldier. После смены
класса/цвета и отключения владельца трупы остаются в сцене. В демо меняются
`teamcolor` / `enemycolor`, индивидуальный `red_team_color`, выключается
перекраска и переключается `gl_nocolors`. Генератор задаёт все команды сам:

```powershell
py -3.13 tools/tf_model_skin_fixture.py --runtime .codex_tmp/tf-model-runtime --source C:/Games/qwtf --tf-root C:/PythonProjects/TF2003
```

Запустить клиент с этим basedir, `-game fortress -condebug +exec fixture.cfg`.
`vid_renderer 0` проверяет классический OpenGL, `1` — современный.
Сцена использует BSP без поверхностей мира для видимости всех моделей;
скриншоты сохраняются в `fortress`, завершение отмечается
`TF_FIXTURE_COMPLETE` в `qw/qconsole.log`. Это проверка сетевых состояний
и рендеринга в MVD, а не интерактивная проверка игрового процесса на сервере.
